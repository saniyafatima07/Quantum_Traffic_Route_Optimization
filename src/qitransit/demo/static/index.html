How to read this

    

    

      
Modelled: travel time, distance and congestion externality priced by a
         BPR congestion model, the same for every method. This is what the optimiser minimised.

      
Measured: the same routes driven through SUMO: Krauss car-following,
         junction dynamics, signal cycles, lane-changing. The optimiser cannot see any of it, so
         agreement between the two columns is evidence the model is worth optimising against, and
         disagreement is evidence that it is not enough.

      
Per vehicle: time and distance are shown per vehicle in both groups, never
         as a fleet total beside a per-vehicle mean. The objective itself is a fleet total, which is
         correct for ranking methods but not for reading against the measurements.

      
model err %: how far SUMO's journey time sat from the modelled time for
         the same routes. It is the honest measure of how much the surrogate can be trusted, and it
         is reported whether or not it flatters the model.

      
Every objective re-scores its own routes. A method's reported objective is
         recomputed from the exact route set that was handed to SUMO, so the two columns in a row
         always describe the same plan.

      
Fleet: a mixed delivery fleet (van, truck, auto-rickshaw), all at the
         delivery vehicle class because that is the only class every lane in the OSM
         import permits. Departures are staggered over a 30-minute peak.

      
open in SUMO: launches sumo-gui on the selected routes file, so the plan
         can be watched rather than taken on trust.
